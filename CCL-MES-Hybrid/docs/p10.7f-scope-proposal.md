## Q1 — xlsx export engine

The `/summary-report` JSON (7e Q8) already carries every field the
CCL-10-F6 form needs. 7f turns it into a downloadable `.xlsx` that
matches the paper layout so QA can file/print it.

**Recommended**: **server-side render via `DocumentFormat.OpenXml`
(OpenXmlPackage)** in a new `GET {id}/summary-report.xlsx` endpoint
(QcRead policy, content-type `application/vnd.openxmlformats-...`,
`Content-Disposition: attachment; filename="CCL-10-F6_<WoNo>.xlsx"`).
The UI adds a "Tải báo cáo (.xlsx)" button on ShippedSummaryDashboard
that hits the endpoint. Single source of truth — the xlsx is rendered
from the SAME `WoSummaryReport` the JSON endpoint returns, so the
table and the file never drift.

**Trade-off**:
- (+) `DocumentFormat.OpenXml` is the Microsoft-supported, dependency-
  light path (no native libs, works on the SQLite deploy box).
- (+) Reuses the existing live-recompute — late `/run/qty/correct`
  corrections flow through to the file.
- (−) OpenXml is verbose (cell-by-cell). Mitigation: a small
  `Ccl10F6Writer` helper keeps the layout map in one place + a
  golden-file fixture (byte-shape, not byte-identical) locks the
  column/row positions.
- (−) Client-side (ClosedXML in Blazor WASM) was considered + rejected
  — the report needs server-only fields + the auth gate lives server-
  side anyway.

**Contract gap**: SpecHub is silent on whether the xlsx is generated
on-demand (every download recomputes) or snapshotted at SHIPPED. Same
answer as Q8 — **on-demand / live** for consistency with the JSON.

## Q2 — pause pareto + OEE charting

7e shipped `pausePareto` as a flat table + the OEE factors as bare
numbers. 7f visualises them in the summary card.

**Recommended**: **inline SVG charts rendered in Razor (no JS charting
dependency)** — a horizontal bar pareto for pause reasons (sorted desc
by total_seconds) + a 3-segment OEE gauge (availability × performance
× quality). Pure-C# SVG path math keeps it Catalyst/WASM-safe and
testable via bUnit (assert the `<rect>` widths are proportional to the
data). When `performance` is null (Machine.PlannedUnitsPerHour absent
— see 7e Q8 trade-off), the gauge renders "—" for that segment + a
hint, never a broken chart.

**Trade-off**:
- (+) Zero new JS dependency; renders identically on server + WASM +
  in the xlsx (the SVG can be rasterised into the file or the file just
  carries the pareto table — see Q3).
- (−) Hand-rolled SVG is less featureful than a charting lib. Fine for
  a static report card; interactive drill-down is not a go-live need.

## Q3 — does the xlsx embed the charts or just the tables?

**Recommended**: **tables only in v1** — CCL-10-F6 is a print/file
form; the pareto + OEE land as plain cells (reason / count / seconds
rows + the 4 OEE factors as a labelled row). Chart images in xlsx need
the OpenXml DrawingML surface (heavy). Defer embedded charts to a 7f.2
follow-up if QA asks.

**Trade-off**: (+) ships the operator-critical artifact (the signed
report) fast; (−) the printed file is less pretty than the on-screen
card. Acceptable — the screen card has the charts (Q2).

## Q4 — Catalyst camera capture for QC photos

7e shipped photo upload via a **file-picker** (`QcPhotoStrip`). 7f adds
**live camera capture** so the operator photographs the NG part at the
station without a separate gallery step.

**Recommended**: **MAUI `MediaPicker.CapturePhotoAsync` on the
Catalyst/MAUI shell + graceful `<input type="file" capture>` fallback
on the web client**. The capture returns a stream that flows into the
SAME `POST {id}/qc/{kind}/items/{itemKey}/photos` endpoint 7e already
ships — no new server surface, only a new client capture affordance +
the IBlobStore caps (`MES_BLOB_MAX_BYTES`, allowed extensions) already
guard it.

**Trade-off**:
- (+) Reuses the entire 7e photo wire + blob-store security guards.
- (+) Web fallback means the feature degrades, never breaks, off-MAUI.
- (−) Camera permission + device-orientation handling is MAUI-platform
  work (iOS/Android/Windows each differ). Mitigation: keep it behind a
  capability check; absent camera → the existing file-picker stays.

**Contract gap**: none — additive client affordance on a locked
endpoint.

## Q5 — audit + i18n surface for the export

**Recommended**: emit a `WO_REPORT_EXPORTED` audit row on each xlsx
download (actor + WO + format) so QA filing is traceable; add EN+VI
keys for the new button + chart labels + camera affordance per the
i18n parity rule. New audit code mirrors the 7e naming.

**Trade-off**: (+) closes the "who pulled the signed report" question
for compliance; (−) one more audit code — trivial.
