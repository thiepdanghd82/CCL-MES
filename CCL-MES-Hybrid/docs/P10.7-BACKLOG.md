## 2. Backward force paths beyond `SETTING → PREPRESS`

**Decided**: 2026-06-05, P10.7a-2.3 closeout (matrix locked).
**Contract**: §3.1 transition grid + §8.1-backlog amendment block.

**Current matrix**: 11 cells are forceable per §3.1 `recovery-only`
classification — `SETTING → PREPRESS` + `*→ CANCELLED` for every
non-terminal source. Wedges OUTSIDE of SETTING (e.g. operator stuck
at `IPQC_WAIT` with no IPQC available) have only "wait OR force-cancel"
as recovery options.

**Why deferred**: keeping the matrix tight matches §2.2 terminal-states-
no-revive philosophy. Reworks emit a fresh WO via `SPEC_REVISE` rather
than reviving a wedged one.

**Revisit trigger**: operational data showing IPQC_WAIT or FQC
wedges happen frequently enough that force-cancel + re-issue feels
disruptive. Specifically: ≥3 distinct cases / month of "operator at
IPQC_WAIT with no IPQC for >30 min" OR "FQC inspector left mid-shift
with WO at FQC_PENDING".

**Required change path**: amendment PR that edits `§3.1` grid AND
`WorkOrderStateMachine.ClassifyTransition` AND
`WorkOrderStateMachineIsForceableTests` AND the §3.2 audit-event table.
**DO NOT** smuggle additional cells into `IsForceablePhase` without the
contract amendment — the 144-cell matrix test catches that.

**Estimated effort if revived**: ~3d (per cell pair added: contract
amendment + state-machine entry + matrix test update + audit emit
event name reservation).
