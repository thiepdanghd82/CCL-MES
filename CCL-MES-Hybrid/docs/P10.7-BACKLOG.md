## 2. Backward force paths beyond `SETTING → PREPRESS`

**Decided**: 2026-06-05, P10.7a-2.3 closeout (matrix locked).
**Contract**: §3.1 transition grid + §8.1-backlog amendment block.

**Current matrix**: 11 cells are forceable per §3.1 `recovery-only`
classification — `SETTING → PREPRESS` + `*→ CANCELLED` for every
non-terminal source. Wedges OUTSIDE of SETTING (e.g. operator stuck
at `IPQC_WAIT` with no IPQC available) have only "wait OR force-cancel"
as recovery options.

**Why deferred**: keeping the matrix tight matches §2.2 terminal-states-
no-revive philosophy. Reworks emit a fresh WO via `SPEC_REVISE` rather
than reviving a wedged one.

**Revisit trigger**: operational data showing IPQC_WAIT or FQC
wedges happen frequently enough that force-cancel + re-issue feels
disruptive. Specifically: ≥3 distinct cases / month of "operator at
IPQC_WAIT with no IPQC for >30 min" OR "FQC inspector left mid-shift
with WO at FQC_PENDING".

**Required change path**: amendment PR that edits `§3.1` grid AND
`WorkOrderStateMachine.ClassifyTransition` AND
`WorkOrderStateMachineIsForceableTests` AND the §3.2 audit-event table.
**DO NOT** smuggle additional cells into `IsForceablePhase` without the
contract amendment — the 144-cell matrix test catches that.

**Estimated effort if revived**: ~3d (per cell pair added: contract
amendment + state-machine entry + matrix test update + audit emit
event name reservation).

## 3. NG co-sign on `wo_materials.status = NG`

**Decided**: 2026-06-06, P10.7b breakdown approval.
**Contract**: §5.1 row `wo_materials` (currently no `requires-signoff`
flag on NG) + §2.2 row PREPRESS ("Exit by OP role" — single-operator
authority on the parent state).

**Why deferred**: contract §2.2 leaves PREPRESS as operator-only;
adding a supervisor co-sign on individual NG rows is an additive
flag, not a contract violation, but is unnecessary for go-live. The
4-eye gate triggers at SETTING_DONE exit (1-op-lock — out of 7b
scope) and at IPQC (true 2-person modal — 7c work).

**Revisit trigger**: post-go-live audit showing material defect /
lot-number mistake escaping past PREPRESS into RUNNING multiple
times because an operator marked NG without flagging supervisor.
Specifically: ≥5 distinct cases / month where a `wo_materials.status =
NG` row is later overridden during IPQC re-inspection, indicating
the original NG decision needed a second pair of eyes.

**Required change path**: §5.1 amendment adding a `requires-signoff`
column to the `wo_materials` write contract + new
`AuditAction.WO_PREPRESS_NG_COSIGN` event + Razor co-sign modal in
the Hybrid client + supervisor-role bUnit fixtures.

**Estimated effort if revived**: ~4d (1d contract amendment + 1d
server enforcement + 2d Catalyst UI co-sign modal).

## Adding a new item

Open this file, add a new `## N. <Title>` section, fill every header
(Decided / Contract / Why deferred / Revisit trigger / Required change
path / Estimated effort). The Required change path field is the
operational guardrail — it tells the next agent EXACTLY which files
need amendment so the change cannot be smuggled in via the wrong
surface.
