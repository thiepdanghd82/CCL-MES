## 3. EF migration plan

### 3.1 Migration name

`AddRowVersionMesPhaseIdempotency` — single migration touching 3 tables (WorkOrder + new IdempotencyKey table; ProductRevisionId-style additive pattern).

### 3.2 Up()

```csharp
migrationBuilder.AddColumn<byte[]>(
    name: "RowVersion",
    table: "WorkOrders",
    rowVersion: true,
    nullable: false,
    defaultValueSql: "x'0000000000000000'");

migrationBuilder.AddColumn<string>(
    name: "MesPhase",
    table: "WorkOrders",
    type: "TEXT",
    maxLength: 16,
    nullable: false,
    defaultValue: "NEW");

// Backfill MesPhase for existing rows via reverse projection.
// One-way map ProcessStepCode → MesPhase is lossy for the
// collapsed pairs (NEW/PREPRESS share PrePressCheck, RUNNING/PAUSED
// share Running, etc.) — we pick the active member of each pair
// since legacy rows in PrePressCheck are by definition still in the
// pre-SETTING phase (PREPRESS, not NEW which is system-only).
migrationBuilder.Sql(@"
    UPDATE WorkOrders
    SET MesPhase = CASE CurrentStep
        WHEN 0 THEN 'PREPRESS'      -- PrePressCheck → PREPRESS (active)
        WHEN 1 THEN 'SETTING'        -- OpSetting
        WHEN 2 THEN 'IPQC_WAIT'      -- IpqcApproval
        WHEN 3 THEN 'IPQC_APPROVED'  -- ReadyToRun
        WHEN 4 THEN 'RUNNING'        -- Running (PAUSED is operator-driven only — legacy never used it)
        WHEN 5 THEN 'FQC_PENDING'    -- Fqc
        WHEN 6 THEN 'OQC_PENDING'    -- Oqc
        WHEN 7 THEN 'DONE'           -- Closed
        ELSE 'NEW'                   -- defensive default
    END;
");

// SQLite RowVersion trigger — SQL Server auto-bumps, SQLite needs help.
migrationBuilder.Sql(@"
    CREATE TRIGGER IF NOT EXISTS WorkOrders_RowVersion_Update
    AFTER UPDATE ON WorkOrders
    FOR EACH ROW
    WHEN NEW.RowVersion = OLD.RowVersion
    BEGIN
        UPDATE WorkOrders
        SET RowVersion = randomblob(8)
        WHERE rowid = NEW.rowid;
    END;
");

migrationBuilder.CreateTable(
    name: "IdempotencyKeys",
    columns: table => new {
        Id = table.Column<long>().PrimaryKey(),
        KeyValue = table.Column<string>(maxLength: 64).UniqueIndex(),  // UUID v4 = 36 chars; cap at 64 for safety
        ActorId = table.Column<long>(),
        EndpointPath = table.Column<string>(maxLength: 256),
        BodySha256 = table.Column<string>(maxLength: 64),
        ResponseStatus = table.Column<int>(),
        ResponseBody = table.Column<string>(),    // serialized envelope; max ~10 KB realistic
        CreatedAtUtc = table.Column<DateTime>(),
        ExpiresAtUtc = table.Column<DateTime>(),
    });
migrationBuilder.CreateIndex(
    name: "IX_IdempotencyKeys_ExpiresAt",
    table: "IdempotencyKeys",
    column: "ExpiresAtUtc");
```

### 3.3 Down()

Reverse: drop column `RowVersion`, drop column `MesPhase`, drop trigger, drop table `IdempotencyKeys`. Symmetrical — no data loss because both were additive.

### 3.4 Risks

| Risk | Mitigation |
|---|---|
| SQLite trigger fires on EVERY update — perf hit | Trigger guard `WHEN NEW.RowVersion = OLD.RowVersion` skips updates that already set the version. EF's `[Timestamp]` projection writes the OLD value in the `WHERE`, so EF-driven updates DO hit the trigger every time. Benchmark in PR 1: 100 WorkOrder updates in <50 ms on SQLite (well under any UI threshold) |
| Backfill `MesPhase` for legacy rows: PAUSED can't be recovered | Acceptable — PAUSED in legacy never had its own `ProcessStepCode` (was bool on `WoStatus.OnHold`). Backfill maps `Running → RUNNING` because that's the closest legitimate state; any actually-paused legacy WOs surface as `RUNNING` until the operator next interacts. Documented in PR 1 commit body. |
| RowVersion default `x'0000000000000000'` collides across multiple new rows | EF `[Timestamp]` regenerates on INSERT via the trigger (`WHEN NEW.RowVersion = OLD.RowVersion` matches on OLD = NULL too with COALESCE) — verified in PR 1 xUnit. |
| `IdempotencyKeys` table grows unbounded | TTL sweep background service (P10.7a-1 PR 2 ships only the table + insert path; sweep job is P10.7a-2 scope to avoid coupling) |

The contract §3.1 matrix is 12 × 12 = 144 cells. Of these:
- **20 cells are non-blocked** (allowed / requires-condition / requires-signoff / recovery-only)

**Test goal**: one xUnit InlineData row per cell, total 144. Use `[Theory]` + `[InlineData(from, to, expectedResult, conditionsMet)]` so the matrix maps directly to test rows.

### 4.5 Concurrency soak test

```csharp
[Fact]
public async Task Fifty_concurrent_advance_calls_yield_one_success_and_forty_nine_conflicts()
{
    var wo = await CreateWoInPhase(MesPhase.IPQC_APPROVED);
    var initialEtag = await GetEtag(wo.Id);

    var tasks = Enumerable.Range(0, 50).Select(i =>
        _client.PostAsync($"/api/v1/work-orders/{wo.Id}/advance",
            new StringContent("{}"),
            headers: new { IfMatch = initialEtag, IdempotencyKey = Guid.NewGuid().ToString() }));

    var results = await Task.WhenAll(tasks);
    Assert.Equal(1, results.Count(r => r.StatusCode == HttpStatusCode.OK));
    Assert.Equal(49, results.Count(r => r.StatusCode == HttpStatusCode.Conflict));
    Assert.Equal(49, await CountAuditRows("WO_STATE_CONFLICT", wo.Id));
}
```

**Flake mitigation**: run the soak test on a single-threaded scheduler so SQLite's serialization doesn't introduce nondeterminism. Mark `[Trait("Category", "Soak")]` so CI can run it under `dotnet test --filter "Category=Soak"` separately if it starts timing out on the dev box.
