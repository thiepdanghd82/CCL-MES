## 4. Dữ liệu `Data/` — **lỗi chặn, ưu tiên cao nhất**

**443 / 479 file `.xlsx` trong `Data/` hiện không đọc được bằng openpyxl,
pandas hay markitdown.**

Riêng `Data/Spec Excel/`: **335 / 338** file hỏng.

### Nguyên nhân

File chứa entry `xl/SharedStrings.xml` (**S hoa**). openpyxl tìm
`xl/sharedStrings.xml` (**s thường**). Tên entry trong ZIP phân biệt hoa
thường, nên mọi thư viện nền openpyxl đều ném:

```
KeyError: "There is no item named 'xl/sharedStrings.xml' in the archive"
```

File không hỏng — bảng bên trong nguyên vẹn. Chỉ sai hoa/thường ở tên entry.

Sheet trong các file này tên `TDSheet` — chữ ký của bộ xuất **1C:Enterprise**.
Đây là lỗi phía công cụ xuất, sẽ lặp lại với mọi lô spec mới, không phải sự cố
một lần.

### Ảnh hưởng

Mọi đường import spec bằng Python/openpyxl đều chết trên 93% dữ liệu.
`scripts/SpecImportBatch` cần kiểm tra xem có dính không. Nếu import đang chạy
qua ClosedXML/EPPlus phía .NET thì có thể đang thoát — cần xác nhận, đừng
đoán.

### Cách sửa — đã kiểm chứng

```bash
TOOL=~/Documents/"Claude Skills"/tools/xlsx_casefix.py

python3 "$TOOL" "Data" --check                    # đếm, không ghi gì
python3 "$TOOL" "Data/Spec Excel" -o /tmp/fixed   # sửa ra bản sao
python3 "$TOOL" "Data" --in-place                 # sửa tại chỗ, giữ *.xlsx.bak
```

Đã chạy thử 32 file `Data/Spec Excel/FG Silk_Spec Dập/`: sửa xong **32/32 đọc
được**, openpyxl thấy sheet `TDSheet`, markitdown ra ~10 000 ký tự mỗi file,
cấu trúc đồng nhất trên 60 file mẫu (1 sheet, cùng header
"Công ty TNHH CCL Design Việt Nam / PRESS PRODUCT SPECIFICATION").

### Đề xuất chặn tái phát (Nguyên tắc II)

Chuẩn hoá ngay ở cổng nhận file, không sửa thủ công từng đợt: trước khi
import, chạy `needs_fix()` và ghi lại tên entry. Nếu import phía .NET không
dính lỗi này thì vẫn nên chặn ở cổng — để đường Python (báo cáo, đối soát,
migration) không chết về sau.
